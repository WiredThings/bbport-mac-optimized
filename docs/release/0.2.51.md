# 0.2.51 — Tessellation layout and shader-library experiment

- Link Metal tessellation patch inputs to the control shader's actual output layout.
  Previously, unused leading fields could shrink a 224-byte output to a 160-byte input,
  making the strict pipeline check reject the draw. Field offsets, types and stride are
  checked; the guard is retained. Only the affected variants get new cache names.
- Include each compiled module's identity in in-memory pipeline keys. Metal can return
  the same function object for distinct modules whose MSL is identical but whose global
  resource binding numbers differ. Their binding metadata must remain independent.
- Add **Reuse identical Metal libraries** under experimental Metal options, default OFF.
  It uses weak references and complete effective-source/entry/math-option keys. It does
  not keep extra GPU objects alive, change texture-cache capacities, or restore offline
  precompilation. Practical performance benefit remains unconfirmed.
- Existing resolution, effects, two-level addressing, velocity/motion-blur bypass,
  occlusion, resource-lifetime safeguards, Chinese support and online routing remain.
  Normal saves, preferences and existing caches are preserved.

The targeted GPU suite covers leading/middle/trailing unused patch fields, two producer
strides, cold and cached translation, invalid layouts, concurrent library reuse, weak
ownership and retry/capacity boundaries. All 21 tessellated pipeline keys in the private
current-game corpus build cold and from cached MSL. No game shaders or saves are shipped.
A directed binding test fails with the former PSO key and passes with module identities.

Gameplay and measurement results are recorded in
[the follow-up report](METAL-TESSELLATION-AND-LIBRARY-REUSE.md).
Recovery tests use the same request entry as F3; automated deaths use the private game-thread
SetHp tool, not enemy combat. Fresh live-server and physical-key tests are separate limits.
The development driver is excluded from the release.

The final fixed-camera ABBA averaged 48.68 → 49.56 FPS with no scored swap growth; this short comparison does not establish a repeatable gain or 60 FPS. The library experiment remains OFF. See the aggregate for accounted-memory and coverage limits.
