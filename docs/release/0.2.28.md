# Bloodborne Optimized 0.2.28 (0228)

[English user guide](../USER_GUIDE.md) · [中文使用指南](../USER_GUIDE.zh-CN.md) · [Branch changes and third-party credits](../THIRD_PARTY_CHANGES.md)

## Install

Download `Bloodborne-Optimized-0.2.28-macOS.zip` from this fork's Releases page,
extract it and replace `Bloodborne Optimized.app` in Applications. Requires Apple Silicon,
macOS 26 or newer, Rosetta 2 and your own decrypted Bloodborne game folder merged with
update 1.09. This build is ad-hoc signed and is not Apple-notarized.

Existing save paths, controller mappings, selected resolution, effects and optimization choices
are retained. It uses the same production runtime and renderer as the tested 0.2.27 build.
The launcher/runtime use Rosetta where required; direct Metal rendering does not make the
original game an ARM-native port. Vulkan remains available as a compatibility backend.

## Changes since the previously published source

- Reclaim only idle, CPU-invalid sampled texture copies after GPU completion. Render targets,
  storage/display/depth/MSAA textures, active bindings, scene proxies and valid cache entries
  are excluded. Cache capacities and image quality are unchanged; reference path is available
  with `BB_TEXTURE_INVALID_RECLAIM=0`.
- Expose that already-enabled reclamation in the launcher's 25 Metal optimization controls.
  The default policy is 20 ON / 5 optional experiments OFF; saved explicit choices take priority.
- Hide HDR, RCAS/sharpness, background preupload and Vulkan validation when using Metal.
  Preserve their preferences for Vulkan. CPU readback controls remain functional.
- Label Metal presentation by its two actual behaviors: VSync or unsynchronized. Preserve the
  effective behavior of old Immediate/relaxed-FIFO settings and retain Vulkan's four choices.
- Gate alpha merge on actual MetalFX use without discarding the saved preference. Turning
  GPU timing OFF now clears old timing variables that could bypass the checkbox.
- Correct frame-limit zero to mean no additional limit. Shorten English, Simplified Chinese
  and Traditional Chinese descriptions; keep experiment uncertainty and memory costs visible.

## Validation and limits

36 Swift tests and 2 mock-runtime launch-profile tests passed. Native UI inspection checked
Metal and Vulkan control visibility; game settings and original saves were preserved. The
ordered 36-patch Metal series reconstructs the current renderer source without overwriting
unrelated changes.

For reclamation, an earlier isolated Old Yharnam/Dream round-trip comparison settled at
6163.10 versus 5880.30 MiB process footprint; explicitly invalid sampled copies fell from
296.12 to 0 MiB while clean cached backing remained about 303 MiB. Final camera-matched
50-second windows observed 36.19 versus 35.99 FPS. These are limited memory-lifetime
measurements, not a repeatable FPS gain or a guarantee of 60 FPS. No new gameplay benchmark
was run for the launcher-only 0.2.28 update.

## Distribution contents

The app contains no game executable/data, saves, shader caches, downloaded mods, World Warper,
QA apps, route recordings, private automation controllers or sampling artifacts. The credited
Hunter's Mark launcher artwork is the intentional icon asset. Local benchmark/analyzer scripts
are omitted from this public app archive; developer runtime diagnostics remain off in normal Play.

The source archive and Git tag provide the launcher, runtime integration, pinned submodule
sources and adapter patches. See [SOURCE.md](SOURCE.md) for build and dependency instructions.
